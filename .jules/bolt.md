## 2025-05-15 - [Generator Prompt Caching and Rendering Optimization]
**Learning:** Jinja2 template parsing in the `Prompt` class is a significant bottleneck, especially for large templates. Re-instantiating the `Prompt` object in each call to `Generator.get_prompt` or `Generator.call` adds considerable overhead (~20ms per call). Furthermore, double-rendering the prompt (once for tracing and once for the model call) unnecessarily doubles this overhead.
**Action:** Always cache objects that perform expensive initialization (like template parsing). In `Generator`, caching the `Prompt` builder and reusing the rendered `prompt_str` in `_pre_call` reduced latency by orders of magnitude (~90x for total call, ~350x-900x for prompt generation). Use identity checks (`is`) for reliable and fast cache invalidation of internal builders.
