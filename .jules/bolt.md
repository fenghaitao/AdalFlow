## 2025-05-15 - [Generator Prompt Caching Optimization]
**Learning:** Instantiating the `Prompt` builder in the `Generator`'s `get_prompt` and `call` methods on every invocation is a significant bottleneck (~22ms for large templates) due to repeated Jinja2 template parsing. Caching the `Prompt` instance and only recreating it when `template` or `prompt_kwargs` identity changes provides a dramatic speedup. Additionally, double-rendering the prompt (once for spans/logging and once in `_pre_call`) adds unnecessary overhead.
**Action:** Always check for redundant object instantiation and repeated expensive operations like template rendering in "hot" execution paths of the `Generator` and other core components. Use identity checks (`is`) for efficient cache invalidation when dealing with potentially large dictionaries or strings.
