## 2025-05-22 - [Generator Performance Bottleneck: Prompt Re-creation]
**Learning:** Instantiating the `Prompt` class in the `Generator` class for every call or utility method (like `get_prompt`, `print_prompt`, etc.) introduces significant overhead, especially with large templates, due to Jinja2 template environment setup and parsing (~7ms for default templates). Additionally, double-rendering the prompt in `call`/`acall` sequences (once for span tracking/caching and once in `_pre_call`) further increases latency.
**Action:** Implement lazy caching of the `Prompt` instance within the `Generator` and optimize the call sequence to pass the pre-rendered prompt string, avoiding redundant rendering and object creation. This reduces `Generator.call` latency by ~50x on average.
