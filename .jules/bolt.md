## 2025-05-15 - [Generator Prompt Caching]
**Learning:** Re-instantiating the `Prompt` object in every `Generator` call (including `get_prompt`, `print_prompt`, and `_pre_call`) is a significant performance bottleneck (~9ms per instantiation) because it triggers Jinja2 template parsing every time. By caching the `Prompt` instance and only re-creating it when the template or `prompt_kwargs` dictionary identity changes, performance can be improved by over 100x for simple templates and potentially 1400x for large, complex ones. Additionally, `Generator.call` and `acall` were double-rendering the prompt (once for the span/logger and once in `_pre_call`), which can be eliminated by passing the rendered string to `_pre_call`.
**Action:** Always check for redundant object instantiations that involve expensive parsing or I/O, especially within high-frequency loops or "hot path" methods like `Generator.call`. Implement lazy loading/caching for these objects with proper cache invalidation logic based on state changes.
