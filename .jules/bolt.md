## 2025-05-22 - [Optimized BM25Retriever with Inverted Index]
**Learning:** The previous implementation of `BM25Retriever` had $O(Q \cdot N)$ complexity for scoring, where $Q$ is the number of query terms and $N$ is the total number of documents. By implementing an inverted index and using NumPy vectorization, complexity was reduced to $O(Q \cdot \text{avg\_df})$, where $\text{avg\_df}$ is the average document frequency of query terms. Additionally, `Component.from_dict` uses `__new__` and bypasses `__init__`, which means internal state like `_components` and `_parameters` must be manually initialized if they are needed before a full object restoration.
**Action:** Always prefer inverted indices for text retrieval components. When extending `Component.from_dict` or using non-serialized caches, ensure internal base class structures are properly initialized if `__init__` is bypassed.
